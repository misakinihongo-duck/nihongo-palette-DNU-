# Nihongo Palette 開発計画

このドキュメントでは、Nihongo Paletteの開発フェーズと主なタスクを時系列でまとめます。各フェーズは約1週間を想定していますが、状況に応じて調整します。

## Phase 1: UI骨格の作成

- Next.jsプロジェクトをTypeScriptとTailwind CSSでセットアップする。
- レイアウトコンポーネントを作成：ヘッダー、サイドバー、メインコンテンツエリア。
- 先生/生徒選択用の仮ログイン画面を実装する（認証は不要）。
- モックデータを用いて、教師ダッシュボードと生徒ダッシュボードの仮画面を実装する。
- 作文ワークスペースの3カラムレイアウトを作成し、講師Viewと生徒Viewを仮分離する。

## Phase 2: 作文ワークスペース機能実装

- 入力された日本語文章にふりがなを表示する機能を実装する。
- 先生が修正内容をメモして保存できる添削履歴機能を作成する。
- 作文中の単語を選択して単語帳へ追加するUIを追加する。
- データはローカル状態またはモックストレージに保存し、DB接続は次のフェーズまで導入しない。

## Phase 3: Teacher Support Panel

- OpenAI APIと通信するサーバー側APIルートを用意する。
- 先生がテキストを選択して、やさしい英語説明・やさしい日本語説明を生成する機能を追加する。
- Teacher Support PanelのUIを作成し、選択語に応じて説明を表示できるようにする。
- Panelは講師Viewのみに表示し、生徒Viewには表示しない。

## Phase 4: JLPT記事生成

- JLPTレベルとトピックを入力するフォームを実装する。
- OpenAI APIを用いて約400字の記事と語彙リストを生成する処理を実装する。
- 生成した記事と語彙を表示し、保存できるようにする。
- 語彙リストは単語クイズに流用できるように後続フェーズへのインターフェースを設計する。

## Phase 5: 単語クイズ生成

- 保存済みの語彙リストからクイズを生成する機能を実装する。
- 問題形式は、意味を問う問題、穴埋め問題、実践的な会話形式など複数用意する。
- クイズ結果を表示し、正答率や学習履歴の基礎となる情報を保存できるようにする。

## Phase 6: データベース統合

- Supabaseプロジェクトを作成し、PostgreSQLテーブルを設計する。
- Supabase Authを導入して先生と生徒のログイン機能を実装する。
- 作文、添削履歴、語彙リスト、記事、クイズデータなどをSupabaseに保存するようにする。
- 行レベルセキュリティ（RLS）で、先生は担当生徒のデータのみ、生徒は自分のデータのみ参照できるようにする。

## Phase 7: デプロイとテスト

- Next.jsアプリをRenderにデプロイするための設定を行う。
- 本番環境で全機能をテストし、UI/UXの改善点をフィードバックとして反映する。
- 先生と生徒に試用してもらい、追加要望やバグ報告を反映する。
